# 02 · 鉴权接入指南

本指南面向把「变电智能问数」专家包从 **Mock 联调** 切换到 **中台真实接口** 的接入人员。所有凭证只从环境变量读取，代码中不包含任何真实 appKey / appSecret / Token。

> 二期（`expert-pack-2`）已内置本地可鉴权模拟网关：`pms_cli.py mock-server`，可在没有真实凭证时走通 token / appkey 的完整 HTTP + 鉴权链路，见 [09-模拟网关与鉴权](09-模拟网关与鉴权.md)。

## 一、当前状态（先读这一段）

| 项目 | 现状 | 影响 |
|---|---|---|
| 默认鉴权模式 | `PMS_AUTH_MODE=mock` | 开箱可用，返回 `spec/interfaces.json` 中的内置样例数据，**不发起任何真实请求** |
| appKey 签名算法 | 已实现**模拟规范**（`pms_client/signing.py`：7 段 canonical + HMAC-SHA256 小写 hex、毫秒时间戳、±300s 时间窗、nonce 防重放） | 本地可用（搭配 `pms_cli.py mock-server --auth-mode appkey`）；真实中台规范不同则只替换 `signing.py` 实现，见第五节 |
| token / none 模式 | 已实现，可配置 | token 需真实令牌；none 仅用于网关侧免鉴权/代理鉴权的内网环境 |
| 接口地址与参数 | `spec.status = inferred`，为推断的占位规格 | 正式《接口说明文档》下发后先修订 spec，再联调（见 [04-开发与扩展指南](04-开发与扩展指南.md)） |
| 真实凭证 | **本包不包含** | 任何情况下不得把凭证写进代码、文档、截图或提交到仓库 |

## 二、接入与鉴权申请流程

依据原始《变电专业智能问数：优先接入接口（26 个）功能说明》第 3.1 节「接入与鉴权（第一步）」，标准流程如下：

| 步骤 | 责任方 | 要做什么 | 产出 / 验收 |
|---|---|---|---|
| 1. 服务目录检索 | 业务/开发 | 在电网资源业务中台（PMS）服务目录中检索本包涉及的 26 个接口，确认接口编码、所属中心、能力域与版本 | 26 条接口在服务目录中均可检索到，编码与 [01-接口映射表](01-接口映射表.md) 一致 |
| 2. 下载《接口说明文档》 | 开发 | 逐个下载 26 个接口的说明文档，明确请求方式、参数、返回字段与示例、错误码 | 拿到官方接口契约，替换 spec 中的推断值 |
| 3. 提交接入/鉴权申请 | 业务负责人 | 向中台管理部门提交申请，**注明用途（变电智能问数）、调用频率、数据范围**，说明接入系统与联系人 | 申请受理，明确审批周期与配额（QPS） |
| 4. 获取调用凭证 | 中台管理方 | 按平台要求下发 `appKey/appSecret` 或访问 `Token`，以及网关地址、IP 白名单要求 | 拿到凭证与网关地址（**只在受控渠道传递，不落代码库**） |
| 5. 测试环境联调 | 开发 | 按 [04-开发与扩展指南](04-开发与扩展指南.md) 修订 spec → 配置环境变量 → `doctor` 自检 → 单接口调用 → 采样比对返回结构 | 26 个接口在测试环境返回结构与文档一致，错误码可归一 |
| 6. 切生产环境 | 开发 + 业务复核 | 更换 `PMS_GATEWAY_BASE_URL` 与生产凭证，重跑验收清单；保留 Mock 作为回归演示通道 | 生产抽检通过，鉴权失败/限流/超时均有用例覆盖，监控与日志就绪 |

> 申请信息建议一次性写全：接入系统名称、用途「变电智能问数」、涉及接口清单（26 个编码）、预估日/峰值调用量与 QPS、数据范围（组织/站/设备）、使用人员范围、数据留存与脱敏方案、应急联系人。

## 三、环境变量配置

配置由 `skills/pms-gateway-mcp/scripts/pms_client/config.py` 读取（唯一读取点），全部可选，默认即可跑 Mock。

| 变量 | 必填性 | 默认值 | 示例 | 说明 |
|---|---|---|---|---|
| `PMS_GATEWAY_BASE_URL` | 非 mock 模式必填 | 空 | `https://pms-gateway.example.com` | 中台网关完整地址；必须以 `http://` 或 `https://` 开头，接口 path 由网关层拼接 |
| `PMS_AUTH_MODE` | 可选 | `mock` | `mock` / `none` / `appkey` / `token` | 鉴权模式，见第四节；非法值报 `AUTH_MODE_INVALID` |
| `PMS_APP_KEY` | appkey 模式必填 | 空 | `<申请到的 appKey>` | 应用标识；禁止硬编码 |
| `PMS_APP_SECRET` | appkey 模式必填 | 空 | `<申请到的 appSecret>` | 签名密钥；禁止硬编码、禁止进入日志 |
| `PMS_TOKEN` | token 模式必填 | 空 | `<申请到的令牌>` | 以 `Authorization: Bearer <token>` 发送 |
| `PMS_TIMEOUT` | 可选 | `30`（秒） | `30` | 单次请求超时；过小易误判超时，过大影响交互体验 |
| `PMS_RETRY` | 可选 | `1`（次） | `1` | 失败重试次数，仅对超时/网络/429/5xx 等可重试错误生效 |
| `PMS_SPEC_PATH` | 可选（扩展） | 空 | `F:\...\expert-pack\spec\interfaces.json` | 显式指定 spec 路径。**一般无需设置**：底座技能的发布 zip 已内置 spec 快照 `references/interfaces.json`，装完即用；该变量仅用于指向更新版 spec 覆盖内置快照，或本地开发调试 |
| `PMS_VERIFY_SSL` | 可选（扩展） | `1` | `1` / `0` | 是否校验 HTTPS 证书；仅内网自签证书临时调试可置 `0`，生产禁止关闭 |

### 配置示例（PowerShell）

```powershell
$env:PMS_GATEWAY_BASE_URL = "https://pms-gateway.example.com"
$env:PMS_AUTH_MODE       = "appkey"
$env:PMS_APP_KEY         = "<申请到的 appKey>"
$env:PMS_APP_SECRET      = "<申请到的 appSecret>"
$env:PMS_TIMEOUT         = "30"
$env:PMS_RETRY           = "1"
python expert-pack/skills/pms-gateway-mcp/scripts/pms_cli.py doctor
```

### 配置示例（cmd / 系统环境变量）

```bat
set PMS_GATEWAY_BASE_URL=https://pms-gateway.example.com
set PMS_AUTH_MODE=appkey
set PMS_APP_KEY=<申请到的 appKey>
set PMS_APP_SECRET=<申请到的 appSecret>
```

也可以在中台宿主（Claude Desktop 等）的 MCP 配置 `env` 字段中配置，见 [03-部署与使用说明](03-部署与使用说明.md) 的「MCP 宿主配置示例」。

### 安全约定

- 凭证只放环境变量或宿主的 `env` 配置，**不写进 SKILL.md、references、脚本、文档、测试用例**。
- 不提交 `.env`、凭证截图、抓包文件；日志中凭证已做掩码（`AppKey` / `Token` 仅显示首尾少量字符）。
- 建议按「最小权限 + 最小数据范围」申请，按环境使用独立凭证（测试/生产分离），并设置轮换周期。

## 四、四种鉴权模式

| 模式 | 需要的配置 | 行为 | 适用场景 | 当前可用性 |
|---|---|---|---|---|
| `mock` | 无 | 不发起网络请求，按 `spec.tools[].mock` 返回内置样例数据，并带 Mock 标记 | 无凭证联调、演示、自动化测试 | **默认，开箱可用** |
| `none` | `PMS_GATEWAY_BASE_URL` | 不附加鉴权头，直接请求网关 | 内网直连、网关侧已完成统一鉴权/代理认证 | 可用，需网关侧确认 |
| `appkey` | 网关地址 + `PMS_APP_KEY` + `PMS_APP_SECRET` | 生成 `X-PMS-App-Key` / `X-PMS-Timestamp` / `X-PMS-Nonce` / `X-PMS-Signature` 请求头 | 中台下发的 appKey/appSecret 接入方式 | 请求头与签名已就绪（模拟规范，见 `pms_client/signing.py`）；接真实中台时替换签名实现 |
| `token` | 网关地址 + `PMS_TOKEN` | 附加 `Authorization: Bearer <token>` | 中台下发的令牌式接入 | 可用，需有效令牌 |

模式选择顺序建议：**先用 `mock` 把技能与问数链路跑通 → 再按中台实际下发的凭证类型选 `token` 或 `appkey` → 极少数免鉴权内网环境才用 `none`**。缺凭证时网关层会返回可操作的中文错误（`AUTH_MISSING_CREDENTIALS`），不会静默失败。

## 五、AppKey 签名规范与真实中台替换步骤

### 5.1 当前实现（模拟规范）

- **唯一实现**：`expert-pack-2/skills/pms-gateway-mcp/scripts/pms_client/signing.py`；客户端
  `AppKeyAuthProvider.build_headers()` 与本地模拟网关 `mock_gateway.auth` 共用，保证两端逐字节一致。
- **签名串（7 段，`\n` 连接）**：`appKey` / `METHOD`（大写）/ `path`（不含 query）/ 规范化 query /
  `sha256(rawBody)` 小写 hex / 毫秒时间戳 / nonce。
- **规范化 query**：跳过 `None`；列表按逗号拼接；布尔转 `true`/`false`；`(key, value)` 排序后 `urlencode`。
- **最终签名**：`HMAC-SHA256(appSecret, canonical)` 小写 hex，放入 `X-PMS-Signature`；同时携带
  `X-PMS-App-Key` / `X-PMS-Timestamp` / `X-PMS-Nonce`。
- **时间窗与防重放**：本地网关校验 ±300 秒；nonce 内存缓存防重放（重启清空）。
- **重要**：这是为本地联调定义的**模拟规范**，不是中台正式规范，正式接入前不得用于生产。

### 5.2 真实中台规范到位后的替换步骤

1. **拿到《接口说明文档》中的签名规范**，逐项记录（写进内网接入记录，不要写进本仓库）。
2. **只改 `signing.py`**：调整 canonical 拼接顺序、摘要算法/编码、时间戳格式与窗口；若请求头名称不同，
   同步 `signing.py` 顶部的 `HEADER_*` 常量。`transport` / `client` / CLI / MCP Server 及各技能文档
   **均无需改动**（本地模拟网关会自动跟随同一实现）。
3. **配置环境变量**：`PMS_GATEWAY_BASE_URL`、`PMS_AUTH_MODE=appkey`、`PMS_APP_KEY`、`PMS_APP_SECRET`。
4. **自检与联调**：`doctor` → 单个只读接口 → 26 接口抽样（重点 GET/POST、path 参数、分页、空结果）
   → 第六节验收清单；401/403 先查凭证有效期、时钟同步、签名串与 IP 白名单。
5. **切生产**：更换生产地址与凭证，重跑验收清单；保留 Mock 与本地模拟网关作为演示/回归通道。

> 关键承诺：**签名实现是唯一的算法改动点**，且客户端与本地模拟网关共用同一实现，不会出现两端规范漂移。

## 六、联调验收清单

| # | 验收项 | 通过标准 | 检查方式 |
|---|---|---|---|
| 1 | 配置自检 | `doctor` 输出 `ok: true`，无配置问题 | `pms_cli.py doctor` |
| 2 | 工具清单 | 26 个工具齐全，名称与 spec 一致 | `pms_cli.py list-tools` / MCP `tools/list` |
| 3 | Mock 基线 | mock 模式可返回 26 个工具的样例数据 | `pms_cli.py call <tool>` 逐个抽查 |
| 4 | 鉴权连通 | 至少一个真实接口返回 HTTP 200 且业务码为成功 | 测试环境单接口调用 |
| 5 | 凭证缺失处理 | 去掉凭证后返回 `AUTH_MISSING_CREDENTIALS`，提示可操作 | 临时清空变量后调用 |
| 6 | 鉴权失败处理 | 错误凭证返回 `AUTH_FAILED`（HTTP 401/403），不泄露凭证 | 使用过期/错误凭证 |
| 7 | 超时与重试 | 超时返回 `TIMEOUT`，重试次数符合 `PMS_RETRY` | 模拟网络超时 |
| 8 | 限流处理 | 429 返回 `RATE_LIMITED`，提示降低频率/提升配额 | 联调时与中台确认 |
| 9 | 分页与空数据 | 分页参数生效；空结果明确返回空列表/总数，不报错 | 构造无数据条件 |
| 10 | 中文字段 | 中文返回值不乱码、不转义异常 | 检查含中文的接口响应 |
| 11 | 返回结构 | 与《接口说明文档》字段一致，差异已回改 spec | 对照文档逐接口抽样 |
| 12 | 参数风格 | GET query / POST JSON body / path 参数均正确 | 覆盖三类参数风格 |
| 13 | 生产抽检 | 生产环境只读接口抽检通过，未见越权数据 | 生产低峰期抽检 |
| 14 | 文档同步 | [01-接口映射表](01-接口映射表.md)、spec 与代码一致 | 重跑构建校验脚本 |

## 七、QPS / 频控与数据脱敏要求

### QPS 与频控

- **以中台批复为准**：申请时明确 QPS/日调用量上限，联调与生产都不得超过；不同接口可能独立限流。
- **客户端行为**：`PMS_RETRY` 只对超时/网络/429/5xx 等可重试错误生效，默认 1 次；勿为追求成功率盲目加大重试次数或并发。
- **降低调用压力**：优先用分页与条件过滤缩小结果集；同一会话内对同一设备主键的台账查询可复用结果；高频问数场景应加缓存（见 [04-开发与扩展指南](04-开发与扩展指南.md) 与 [05-架构设计](05-架构设计.md)）。
- **避免放大**：一次问数只调用必要接口，不因「多取一点备用」而全量拉取；跨域组合由编排技能串行/按需调用，不做无界并行打满。
- **429 处置**：收到 `RATE_LIMITED` 应退避并提示用户稍后重试，不得在循环中持续重试。

### 数据脱敏

- **对外输出脱敏**：手机号、身份证号、详细地址、用户姓名等敏感字段在回答中做掩码（如 `138****1234`），只保留业务必要的粒度。
- **最小必要**：只取问数所需的字段与范围，不拉取无关组织/用户明细；专题图等含图元的返回只输出必要说明。
- **日志与错误**：不打印完整凭证（代码已掩码）；错误 `details` 中限制原始报文长度（500 字符）；避免把含敏感字段的响应写入长期日志。
- **数据留存**：联调与演示优先使用 Mock 数据；真实数据不落盘、不外传，演示环境使用脱敏样本。
- **权限边界**：按岗位最小权限申请数据范围；涉及停电影响、可靠性等敏感结论时提示需业务复核（专家包回答模板已内置该约束）。

## 八、常见鉴权错误对照

| 错误码 | 典型原因 | 处置建议 |
|---|---|---|
| `AUTH_MISSING_CREDENTIALS` | 选了 appkey/token 模式但凭证为空 | 配置对应环境变量；未拿到凭证前改用 `mock` |
| `AUTH_SIGNATURE_TODO` | 历史错误码：appkey 签名未实现（二期已实现，**不再抛出**） | 保留用于兼容旧日志；升级到 `expert-pack-2` 后无需处理 |
| `AUTH_MODE_INVALID` | `PMS_AUTH_MODE` 拼错或用了不支持的值 | 改为 `mock` / `none` / `appkey` / `token` |
| `AUTH_FAILED` | 凭证过期、错误、时间戳偏移、IP 未在白名单 | 校验凭证有效期与时钟同步；联系中台确认白名单与签名规范 |
| `NOT_CONFIGURED` | 未配 `PMS_GATEWAY_BASE_URL` 或数值型变量非法 | 补全网关地址；`PMS_TIMEOUT`/`PMS_RETRY` 填数字 |
| `SPEC_NOT_FOUND` | 底座 zip 缺少 `references/interfaces.json` 快照（非正常包体），或使用了不完整的自定义打包 | 用 `PMS_SPEC_PATH` 指向 `spec/interfaces.json`，或重新用 `build_pack.py` 生成含快照的技能包 |
| `TIMEOUT` / `NETWORK` | 网络不通、网关不可达、超时过短 | 检查 VPN/代理/DNS；适当增大 `PMS_TIMEOUT` |
| `RATE_LIMITED` | 超过批复 QPS | 降低频率、退避重试，必要时申请提升配额 |

更多运行期问题（空数据、Windows 路径、中文乱码、MCP 宿主启动）见 [03-部署与使用说明](03-部署与使用说明.md) 第八节。
