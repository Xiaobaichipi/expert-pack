# 问数总控 · 指标口径字典

> 本文件是变电智能问数专家包的**指标口径唯一口径表**。所有指标计算必须引用本文件的定义与字段映射。
> 工具名、参数名与返回字段以 `spec/interfaces.json` 为唯一事实源；Mock 模式下全部数值为联调样例。
> 涉及行业规定时限（缺陷消除时限、检修周期、可靠性考核阈值）一律标注「以本单位规程为准」。

## 一、指标总览

| 指标 | 类型 | 主数据源工具 | 前置依赖 |
|---|---|---|---|
| 缺陷率 | 比率 | `inquire_defect` | 设备总台数（`list_psr_by_filters` 的 `total`） |
| 危急/严重缺陷占比 | 比率 | `inquire_defect` | 缺陷总条数 |
| 检修计划完成率 | 完成率 | `get_repair_plan` | 统计截止日、应完成计划清单 |
| 检修及时率 | 及时率 | `get_repair_plan` + `find_repair_test` + `inquire_defect` | 缺陷/计划时限口径 |
| 巡视到位率 | 到位率 | `list_patrol_plan` + `list_patrol_record` | 计划巡视次数、实际巡视次数 |
| 供电可靠率 / 站级可用率 | 比率 | `query_station_scale_analysis` | 统计周期 `startDate`/`endDate` |
| 可开放容量 | 容量值 | `query_open_capacity` | 额定容量、当前负载 |
| 负载率 | 比率 | `query_open_capacity` | 当前负载、额定容量 |

## 二、逐项定义

### 1. 缺陷率

- **定义**：统计期内单位设备（通常按百台设备）发生的缺陷条数，反映设备群体缺陷发生频度。
- **公式**：`缺陷率 = 统计期缺陷条数 ÷ 设备总台数 × 100（百台率）`；如需百分比则 `×100%`，但须在口径中写明是「百台率」还是「占比」。
- **依赖工具与字段**：
  - `inquire_defect` → `total`（按 `startTime`/`endTime` 过滤 `discoverTime`）
  - `list_psr_by_filters` → `total`（设备总台数，按 `stationId`、`deviceType` 过滤）
- **样本要求**：缺陷数与设备数必须是**同一站、同一时间断面、同一设备类型口径**；分母建议用统计期末在运设备数。
- **易错点**：
  - 用当前页条数代替 `total` → 指标失真；
  - 分母混入退役/备用设备 → 缺陷率偏低；
  - 缺陷率与「缺陷占比」混称（前者分母是设备数，后者分母是缺陷数）。
- **展示要求**：写明分子、分母、时间窗、设备类型、是否百台率。

### 2. 危急/严重缺陷占比

- **定义**：危急（或严重）等级缺陷条数占同期缺陷总条数的比例，反映缺陷严重程度结构。
- **公式**：`危急缺陷占比 = 危急缺陷条数 ÷ 缺陷总条数 × 100%`；严重缺陷同理，可并列展示。
- **依赖工具与字段**：`inquire_defect` → `defectLevel`（危急/严重/一般）、`total`。
- **样本要求**：分子分母同一时间窗；缺陷等级以记录字段为准，不按缺陷描述文字推断。
- **易错点**：
  - 缺陷等级三档（危急/严重/一般）与隐患风险三档（重大/较大/一般）混用；
  - 未消除缺陷与已消除缺陷混算未说明；
  - 占比精度虚高（应保留 1 位小数）。
- **展示要求**：总条数 + 各等级条数 + 占比 + 未消除条数。

### 3. 检修计划完成率

- **定义**：截至统计日，已完成的检修计划数占应完成计划数的比例。
- **公式**：`检修计划完成率 = 已完成计划数 ÷ 应完成计划数 × 100%`；**分母只计截至统计日应执行完毕的计划**，未到期计划不计入。
- **依赖工具与字段**：
  - `get_repair_plan` → `planId`、`planTime`、`status`（待执行/执行中/已完成）、`year`/`month`
  - 可选用 `find_repair_test` → `testDate` 交叉验证实际执行
- **样本要求**：同一站/同一设备范围、同一年度；`planTime` 为文本区间时需解析出计划结束日期。
- **易错点**：
  - 把未到期计划计入分母 → 完成率被低估；
  - 用 `status=已完成` 直接等同「已执行」→ 忽略计划态与实际态差异；
  - 计划调整后原计划仍留在列表 → 需以最新计划状态为准。
- **展示要求**：分子、分母、未到期计划数、口径说明。

### 4. 检修及时率

- **定义**：应完成的检修/消缺任务中，在规定时限内完成的比例，反映检修响应与执行及时性。
- **公式**：`检修及时率 = 按时完成项数 ÷ 应完成项数 × 100%`；「按时」判据按业务时限：
  - 危急缺陷一般要求 24 小时内消除；
  - 严重、一般缺陷按本单位缺陷管理规程规定的时限；
  - 计划检修按计划开始/结束时间判定。
  - **上述时限以本单位缺陷/检修管理规程为准**，不同单位可能不同，引用时必须注明。
- **依赖工具与字段**：
  - `inquire_defect` → `discoverTime`、`status`、`defectLevel`，必要时 `view_defect` 取 `processRecords` 中的消除/验收时间；
  - `get_repair_plan` → `planTime`、`status`；
  - `find_repair_test` → `testDate`（实际执行日期）。
- **样本要求**：统计期内**应完成**项；未到期项剔除；同一缺陷只计一次。
- **易错点**：
  - 列表接口无「消除时间」字段时直接算时长 → 需 `view_defect` 补齐，补不齐要说明；
  - 未消除缺陷计为「不及时」但未区分「未到期」→ 结论失真；
  - 计划态与执行态混算。
- **展示要求**：分子、分母、超期清单、时限依据（含「以本单位规程为准」提示）。

### 5. 巡视到位率

- **定义**：实际完成的巡视次数占计划巡视次数的比例，反映运维巡视执行到位情况。
- **公式**：`巡视到位率 = 实际巡视次数 ÷ 计划巡视次数 × 100%`。
- **依赖工具与字段**：
  - `list_patrol_plan` → 计划条数、`frequency`、`startDate`/`endDate`、`status`（未开始/执行中/已完成）
  - `list_patrol_record` → 实际记录条数、`patrolTime`、`patrolType`
- **样本要求**：同一站、同一时间窗；计划条数与记录条数的时间字段不同（计划起止 vs 巡视时间），需按统计期对齐。
- **易错点**：
  - 用「计划状态=已完成」直接当作已巡视 → 应用巡视记录佐证；
  - 频次型计划（每月一次）与记录条数未折算 → 到位率口径需说明是「工单级」还是「点位级」；
  - 未按巡视类型（例行/特巡/熄灯）分类统计 → 结论笼统。
- **展示要求**：计划数、实际数、到位率、按巡视类型分布、口径（工单级近似）。

### 6. 供电可靠率 / 站级可用率

- **定义**：
  - `query_station_scale_analysis` 返回的 `availabilityRate` 为**变电站尺度可用率**（示例 99.982，单位 %）；
  - 行业「供电可靠率（RS-1 / RS-3）」按用户平均停电时间计算，与本接口口径不同。
- **公式**：
  - 站级可用率：以接口返回值直接引用，不自造公式；
  - 参考口径：`RS-1 = (1 − 用户平均停电时间 ÷ 统计期时间) × 100%`（需用户数与停电事件数据，本包暂不提供完整输入）。
- **依赖工具与字段**：`query_station_scale_analysis` → `availabilityRate`、`outageHours`、`outageUserHours`、`outageCount`、`statPeriod`；辅以 `query_outage_incident` → `outageStart`/`outageEnd`、`cause`、`voltageLevel`。
- **样本要求**：统计周期以返回 `statPeriod` 为准；周期不等长时须年化或折算后再比较；不同电压等级不可混算。
- **易错点**：
  - 把站级可用率直接说成「供电可靠率」→ 口径混淆，必须写字段名；
  - 跨周期直接相减/排名；
  - 指标接口 `outageCount` 与事件明细条数不一致未说明。
- **展示要求**：指标值（保留原精度）、统计周期原值、口径名称、单位、与事件明细的一致性说明。

### 7. 可开放容量

- **定义**：设备在满足安全与运行约束前提下，尚可接纳的新增负荷（或接入容量），为分析模型计算值。
- **公式**：以接口返回 `openCapacityMVA` 为准，不由使用方自行相减；自洽校验可用 `额定容量 − 当前负载` 近似对照。
- **依赖工具与字段**：`query_open_capacity` → `deviceId`、`ratedCapacityMVA`、`currentLoadMVA`、`openCapacityMVA`、`loadRate`；台账侧 `get_asset_by_id` → `capacityMVA` 用于校验额定容量一致性。
- **样本要求**：设备级查询按 `deviceId`（示例为资产ID）；站级查询按 `stationId` + `voltageLevel`。
- **易错点**：
  - 用 `rated − current` 替代模型值并宣称等价；
  - 忽略模型约束（N-1、短路容量、间隔资源），把可开放容量当作绝对可接入量；
  - 时点负载当作年度峰值。
- **展示要求**：额定容量、当前负载、可开放容量、负载率、数据时点、说明「模型计算值，接入需专业校核」。

### 8. 负载率

- **定义**：设备当前负载占额定容量的比例。
- **公式**：`负载率 = 当前负载 ÷ 额定容量 × 100%`；以接口返回 `loadRate` 为准，自算结果用于自洽校验。
- **依赖工具与字段**：`query_open_capacity` → `currentLoadMVA`、`ratedCapacityMVA`、`loadRate`。
- **样本要求**：同一时点；三绕组主变按各侧分别统计时须写明侧别。
- **易错点**：
  - 重载/过载阈值自行设定（如 80%/100%）**须以本单位运行规程为准**；
  - 用负载率排序直接下「设备能力不足」结论；
  - 忽略时点性（负载率是快照，非全年峰值）。
- **展示要求**：负载率、当前负载、额定容量、时点、阈值出处。

## 三、跨指标使用纪律

1. **同一回答内口径唯一**：指标名、公式、分子分母、时间窗、主键必须一致；不同口径并列时明确标注。
2. **分母可追溯**：每个比率的分子分母都要能从工具返回中定位（写明工具与字段）。
3. **精度不自造**：接口返回 99.982 就用 99.982%，不自造 100%；占比统一 1 位小数并说明四舍五入。
4. **时间窗必写**：任何指标都带统计起止日期与数据截止时间。
5. **空值即空值**：字段缺失写「未取到」，不参与计算；样本不完整时标注「基于 N 条样本」。
6. **规程兜底**：涉及考核、时限、阈值的规定，一律附「以本单位规程为准」。
7. **Mock 声明**：当前 `PMS_AUTH_MODE=mock`，指标结论仅用于联调演示，不可用于考核、报送或对外发布。
