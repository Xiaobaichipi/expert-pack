# 03 · 部署与使用说明

本说明覆盖三条部署路径：**本地直接运行（开发联调）**、**skillhub 平台发布/安装（交付）**、**MCP 宿主挂载（最终使用，生产环境为内网「腾睿work」/ AgentScope 智能体平台）**。命令以 Windows PowerShell 为主，路径示例按本仓库实际位置书写。

> v1.1.0 起本包共 **12 个技能 = 2 个底座（`pms-gateway-mcp` 数据底座 + `substation-analysis-mcp` 分析底座）+ 6 个业务技能 + 3 个深能力技能（`substation-health-assessment` / `substation-diagnosis` / `substation-report`）+ 1 个总控（`substation-qa-orchestrator`）**，并支持第三个 MCP —— 知识库 MCP（WeKnora，平台已配置）。深能力与知识库的架构、数据流与合规边界见 [06-深能力与知识库集成](06-深能力与知识库集成.md)。

## 一、部署形态与前置条件

| 形态 | 用途 | 需要什么 |
|---|---|---|
| 本地直接运行 | 开发、联调、演示 | Python 3.10+（推荐；本机 3.9.24 已验证可运行）；本仓库源码；默认 Mock 无需网络 |
| skillhub 平台发布 / 安装 | 团队分发、版本管理 | 已登录的 `skillhub` CLI、企业源地址与 API Key |
| MCP 宿主挂载（腾睿work / AgentScope） | 最终用户自然语言问数与深度分析 | Python 可执行文件、两个 stdio MCP 脚本路径、可选的真实网关凭证 |
| 知识库 MCP（WeKnora） | 规程/标准条款引用增强 | 平台侧已建好并在腾睿work 中调通的 WeKnora MCP（本包不重复配置） |

前置检查：

```powershell
python --version                 # 建议 3.10+
skillhub --version               # 发布/安装专家包时需要
python expert-pack/tools/build_pack.py --validate-only
```

> 本包仅依赖 Python 标准库，无需 `pip install`；不要为运行本包引入第三方依赖。

## 二、子技能发布（12 个，按顺序逐个发布）

发布前先登录企业源（`--host` 按你们的企业源地址填写，默认 `SKILLHUB_HOST` 或官方源）：

```powershell
skillhub login --key skh_xxx
```

每个技能是独立目录，**逐个发布**（不要打成一个包）。**发布顺序有依赖关系**：先发两个底座（数据底座 → 分析底座），再发 6 个业务技能，然后发 3 个深能力技能（依赖分析底座），最后发问数总控：

```powershell
$skills = @(
  # 1. 底座（必须先发）
  "pms-gateway-mcp",              # 数据底座：26 个 PMS 接口的 MCP/CLI
  "substation-analysis-mcp",      # 分析底座：7 个分析工具
  # 2. 业务领域（6 个）
  "substation-asset-ledger",
  "substation-device-tree",
  "substation-om-health",
  "substation-maintenance-test",
  "substation-reliability",
  "substation-resource-topology",
  # 3. 深能力（3 个，依赖分析底座）
  "substation-health-assessment",
  "substation-diagnosis",
  "substation-report",
  # 4. 总控（最后发）
  "substation-qa-orchestrator"
)
foreach ($s in $skills) {
  skillhub publish "expert-pack/skills/$s" --changelog "变电智能问数 v1.1.0"
}
```

> 该顺序与 `manifest.json` 的 `skillSlugs` **完全一致**；`build_pack.py` 会校验「前两项为两个底座、最后一项为总控」的顺序契约，改顺序会导致构建失败。

常用参数与建议：

| 操作 | 命令 | 说明 |
|---|---|---|
| 本地预检（不发起请求） | `skillhub publish expert-pack/skills/pms-gateway-mcp --dry-run` | 校验 frontmatter、打包；正式发布前建议每个技能先跑一次 |
| 覆盖版本号 | `skillhub publish <dir> --version 1.0.0` | 默认取 SKILL.md frontmatter 的 `version` |
| 检查已发布版本 | `skillhub search pms-gateway-mcp` / `skillhub install pms-gateway-mcp` | 确认平台可见、可安装 |
| 发布失败 | 看报错；单包必须 ≤ 10MB，目录内不能缺 `SKILL.md` | `build_pack.py` 的打包校验与平台限制一致 |

发布要求（与平台 CLI 实测一致）：每个技能目录根必须有 `SKILL.md`，frontmatter 含 `name`（= 目录名）、`slug`（= 目录名，kebab-case）、`displayName`（中文名）、`description`、`version`（SemVer）。缺 `slug` 会直接报 `Error: SKILL.md 缺少 slug`，缺 `displayName` 同样会被 CLI 拒绝。`__pycache__`、`*.pyc`、`.DS_Store`、`Thumbs.db` 会被自动排除，但建议发布前清理。

## 三、专家包创建 / 上传（skillhub 平台）

专家包（SkillSet / meta-skill）本身**不是一个子技能**，它在平台上引用 12 个子技能（2 底座 + 6 业务 + 3 深能力 + 1 总控），并携带编排提示词 `identify.md`。

### 3.1 在平台创建专家包

1. 进入企业 skillhub 的「专家包 / SkillSet」管理页，新建专家包。
2. 按 `expert-pack/manifest.json` 填写（该文件已对齐平台 SkillSet 清单字段）：
   - `manifestVersion`：`1`；`type`：`skillset`（平台类型；不能再写成旧值 `skillhub-expert-package`）
   - `slug`：`bianya-intelligent-data-qa`（**不可随意改动**，与 identify.md、产物文件名、安装命令一致）
   - `displayName`：`变电智能问数`
   - `summary`：直接复制 `manifest.json` 的 `summary` 字段
   - 场景/子场景：按平台实际类目选择（公开目录无电力类目；本地清单可不填，构建时原样透传）
   - 技能列表：按 `manifest.skillSlugs` 顺序依次选择 **12 个**已发布子技能（顺序见第二节；`skills[]` 的 displayName/summary 由构建脚本从各 SKILL.md 生成，网页端只需按顺序选技能）：
     `pms-gateway-mcp` → `substation-analysis-mcp` → `substation-asset-ledger` → `substation-device-tree` → `substation-om-health` → `substation-maintenance-test` → `substation-reliability` → `substation-resource-topology` → `substation-health-assessment` → `substation-diagnosis` → `substation-report` → `substation-qa-orchestrator`
3. 专家包提示词：上传或以 Markdown 粘贴 `expert-pack/identify.md` 全文（含 frontmatter）。
4. 校验：详情页技能数应为 12；平台「下载 Zip 包」实测**仅含** `manifest.json` + `identify.md`（与 `dist/<pack-slug>-bundle.zip` 结构一致），不含子技能 zip。

### 3.2 本地构建并上传 zip

```powershell
python expert-pack/tools/build_pack.py
```

产物位于 `expert-pack/dist/`：

| 产物 | 结构 | 用途 |
|---|---|---|
| `dist/skills/<slug>.zip` × 12 | zip 根即技能根（`SKILL.md` 在根）；数据底座 `pms-gateway-mcp` 额外内置 spec 快照 `references/interfaces.json`；分析底座 `substation-analysis-mcp` 内置 `config/scorecard.json`、`config/diagnosis_rules.json`、`templates/*.md`（3 个）、`assets/demo_bundle.json` | 单个技能发布/离线分发；两个底座均「装完即用」 |
| `dist/bianya-intelligent-data-qa-bundle.zip` | 构建生成的 `manifest.json` + `identify.md`（`skills[]`/`files[]` 由 `build_pack.py` 从各 SKILL.md 与 identify.md 字节生成；**不含**子技能 zip） | **平台专家包清单包**：与 skillhub.cn 实际下载物（实测仅这两个文件）一致；用于归档/交付，以及企业网页端创建专家包时对照字段 |
| `dist/checksums.txt` | `sha256  相对路径` | 交付校验，逐行可用 `Get-FileHash` 比对 |

> 关键事实（平台实测）：专家包 = 「清单（manifest）+ 编排提示词（identify.md）+ 技能 slug 引用」，**不内嵌子技能 zip**；12 个子技能各自独立发布、独立安装。旧版本文档描述的 `dist/<slug>.zip`「网页导出格式」并非平台真实格式，已从构建产物中移除。

校验产物：

```powershell
Get-Content expert-pack/dist/checksums.txt
Get-FileHash expert-pack/dist/bianya-intelligent-data-qa-bundle.zip -Algorithm SHA256
```

## 四、本地安装专家包

```powershell
# 安装到 Agent 的全局技能目录（不同宿主不同：Claude Code 为 ~/.claude/skills，以宿主实际为准）
skillhub pack install bianya-intelligent-data-qa --dir "$env:USERPROFILE\.claude\skills"

# 覆盖已安装技能
skillhub pack install bianya-intelligent-data-qa --force --dir "$env:USERPROFILE\.claude\skills"

# 机器可读输出（CI/脚本）
skillhub pack install bianya-intelligent-data-qa --json --dir "$env:USERPROFILE\.claude\skills"
```

说明：

- `pack install` 从**平台**按 slug 下载清单包（`manifest.json` + `identify.md`），再逐个下载并安装 `skillSlugs` 中的 12 个技能；请确保平台已存在该专家包且 12 个子技能均已发布。
- 安装结果：`<dir>\<skill-slug>\SKILL.md` 等 **12 个技能目录 + 1 个专家包提示词目录**（`<dir>\<pack-slug>\SKILL.md`，内容为 identify.md），共 **13 个目录**；若清单含 `soul.md`，会写到 `<dir>` 的父目录。重新安装时已存在的技能默认跳过，`--force` 覆盖。
- **`--dir` 必须是 Agent 的全局技能加载目录**，不要指向 `.\skills` 或仓库内 `expert-pack/skills`，否则宿主不会加载这些技能。
- `SKILLHUB_HOST` 环境变量用于指定企业源地址（默认官方源）。
- 离线场景：`skillhub pack install` 没有本地 zip 参数。可解压 `dist/skills/<slug>.zip` 到 `<dir>\<slug>\` 手动安装；专家包提示词则解压 `dist/<pack-slug>-bundle.zip` 的 `identify.md` 为 `<dir>\<pack-slug>\SKILL.md`（目录与文件名与平台安装结果一致）。
- 技能独立安装后，`references/` 中指向本仓库 `docs/`、`spec/` 的相对链接在安装目录下不可用（内容已自带摘要；底座 spec 快照已内置在 zip 内）；以本仓库 `docs/` 原文为准。

## 五、MCP 宿主配置示例

v1.1.0 涉及**三个 MCP Server**：

| MCP Server | 启动入口 | 工具数 | 必需环境变量 |
|---|---|---|---|
| `pms-gateway-mcp`（数据底座） | `expert-pack/skills/pms-gateway-mcp/scripts/mcp_server.py` | 26 | 无（默认 Mock；真实环境需网关地址与凭证） |
| `substation-analysis-mcp`（分析底座） | `expert-pack/skills/substation-analysis-mcp/scripts/analysis_mcp.py` | 7 | 无（纯本地计算，不访问网络/凭证） |
| 知识库 MCP（WeKnora） | 平台侧已配置 | 以平台为准 | 平台侧维护，本包不写死 |

两个 stdio 服务均为**无参数、换行分隔 JSON-RPC 2.0；stdout 只输出协议，日志走 stderr**。宿主统一用 `mcpServers` 结构，`command` 用 `python`、`args` 指向脚本绝对路径。生产环境（内网腾睿work / AgentScope）的注册细节、工具名映射与端到端链路见 [06-深能力与知识库集成](06-深能力与知识库集成.md) 第三节。

通用注意：

- `args` 中的路径建议用**绝对路径**；JSON 中反斜杠要写成 `\\`，或直接用 `/`（本机示例即为 `/`）。
- Windows 上若 `python` 不在宿主进程的 PATH，请把 `command` 换成 Python 的绝对路径（如 `D:/App/Tool/MiniConda/python.exe`）。
- `PMS_SPEC_PATH`：**一般无需设置**。数据底座的发布 zip 已内置 spec 快照 `references/interfaces.json`（构建时由 `build_pack.py` 注入），装完即用；该变量仅用于指向更新版 spec 覆盖内置快照，或本地开发调试时显式指定。
- 分析底座**不需要任何 PMS 变量**：它不取数、不读凭证；其配置来自技能内 `config/*.json`，改动无需改代码。
- Mock 模式无需网关地址与凭证；切真实环境时再补 `PMS_GATEWAY_BASE_URL` 与凭证。

### 5.1 Claude Desktop

配置文件（Windows）：`%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "pms-gateway-mcp": {
      "command": "python",
      "args": [
        "F:/work/2026年/10月/专家包/expert-pack/skills/pms-gateway-mcp/scripts/mcp_server.py"
      ],
      "env": {
        "PMS_AUTH_MODE": "mock",
        "PMS_TIMEOUT": "30",
        "PMS_RETRY": "1"
      }
    }
  }
}
```

保存后完全退出并重启 Claude Desktop，在工具/连接器列表中确认出现 26 个工具。接入真实环境时把 `env` 改为：

```json
      "env": {
        "PMS_GATEWAY_BASE_URL": "https://pms-gateway.example.com",
        "PMS_AUTH_MODE": "token",
        "PMS_TOKEN": "<申请到的令牌>",
        "PMS_TIMEOUT": "30",
        "PMS_RETRY": "1"
      }
```

appkey 模式则把 `PMS_TOKEN` 换成 `PMS_APP_KEY` + `PMS_APP_SECRET`。签名已按「模拟规范」实现（`pms_client/signing.py`，HMAC-SHA256 + ±300s 时间窗）；拿到真实《接口说明文档》后只需替换该实现，见 [02-鉴权接入指南](02-鉴权接入指南.md) 第五节。

```json
      }
    }
```

注册后验证：

1. 宿主工具列表中应出现 7 个工具：`assess_device_health`、`assess_station_health`、`diagnose_equipment`、`detect_defect_patterns`、`compute_device_metrics`、`generate_report`、`list_report_types`；

### 5.6 知识库 MCP（WeKnora）配置

知识库已在腾睿work 侧建好并**通过 MCP 调通**，本包只消费其检索能力，不重复实现：

- 保持平台侧现有 WeKnora MCP 配置（地址、鉴权、知识库 ID）不变，本包不写入任何知识库凭证。
- 若需要在其他宿主（Claude Desktop / Claude Code / OpenClaw）中补齐同一能力，`command` / `args` / `env` 使用平台侧已调通的配置，**不要在本包文档里固化具体变量名**。
- 知识库工具名（如 `search` / `retrieve` / `query`）**以平台实际配置为准**，本包只约定语义槽位；映射与核对方法见 [06-深能力与知识库集成](06-深能力与知识库集成.md) 3.5 节。
- 未挂载知识库 MCP 时必须降级：跳过知识增强，并在结论中注明「未引用规程条款」，不得虚构条款。

### 5.7 内网腾睿work / AgentScope 注册要点

腾睿work（AgentScope 智能体平台，含前端管理界面）通过 **stdio MCP** 挂载两个本地服务，注册时按平台表单填写：

| 平台表单字段 | 数据底座 | 分析底座 |
|---|---|---|
| 名称 / 标识 | `pms-gateway-mcp` | `substation-analysis-mcp` |
| 传输方式 | stdio | stdio |
| 命令 | `python`（或 Python 绝对路径） | 同左 |
| 参数 | `.../skills/pms-gateway-mcp/scripts/mcp_server.py` | `.../skills/substation-analysis-mcp/scripts/analysis_mcp.py` |
| 环境变量 | Mock：仅 `PMS_AUTH_MODE=mock`；真实：补 `PMS_GATEWAY_BASE_URL` 与凭证 | 可选 `PYTHONIOENCODING=utf-8` |

验收：保存后「测试连接」应成功；智能体工具面板应分别可见 26 个与 7 个工具；在会话中问「1号主变健康度如何」应能串起「取数 → bundle → 分析 → 报告」。完整链路、知识库工具名映射与合规边界见 [06-深能力与知识库集成](06-深能力与知识库集成.md)。

## 六、CLI 用法示例

CLI 是 MCP 未挂载时的兜底入口，与 MCP 共用同一实现。

### 6.1 数据 CLI（pms_cli.py）

CLI 位于 `expert-pack/skills/pms-gateway-mcp/scripts/pms_cli.py`，输出为 JSON（中文不转义）。全局可选参数：`--spec <path>`、`--base-url`、`--auth-mode`、`--timeout`、`--retry`、`--compact`；`call` 子命令另有 `--params` / `--params-file` / `--with-items`（额外输出兼容提取后的 items/total）。退出码：`0` 成功；`1` 运行时错误（错误 JSON 打到 stderr）；`2` 参数/用法错误。


## 十、常见问题

### 1）鉴权失败（HTTP 401/403 / `AUTH_FAILED`）

- 确认 `PMS_AUTH_MODE` 与所配凭证匹配（token 配 `PMS_TOKEN`，appkey 配 `PMS_APP_KEY`+`PMS_APP_SECRET`）。
- 确认凭证未过期、网关地址正确、IP 在白名单内、机器时间与网关偏差在允许窗口内。
- appkey 模式签名已实现（模拟规范）；真实中台若返回 401/403，优先核对签名串拼装、时间戳偏差（±300s 窗口）、nonce 是否重复与 IP 白名单，见 02 第五节。
- 先 `mock` 复跑一遍，区分是「鉴权问题」还是「参数/路径问题」。

### 2）返回空数据

- **接口成功但无数据是正常结果**，不得编造或用推测值补齐；回答写「未取到数据」并给出下一步建议。
- 常见原因：`stationId` / `deviceId` / `psrId` 用错主键；时间范围过窄；状态/等级过滤条件过严；分页 `pageNo`/`pageSize` 越界；账号数据权限未覆盖该组织/站。
- 排查顺序：先用 `list-tools` + `describe` 核对参数名 → 放宽过滤条件（只留站/设备）→ 换主键（assetId/psrId/utcNum 互认）→ 查权限。

### 3）请求超时

- 增大 `PMS_TIMEOUT`（如 60），确认 VPN/代理/专线连通性，低峰期重试。
- `PMS_RETRY` 只对超时/网络/429/5xx 生效，不要为了成功率盲目加大；仍失败请联系中台确认网关状态。
- 大数据量查询用分页与条件过滤，避免一次拉全量。

### 4）Windows 路径问题

- 配置中的路径优先用正斜杠 `/`；用反斜杠时必须写成 `\\`（JSON）。
- PowerShell 中路径含空格/中文要加引号；命令参数避免被 `>`、`|` 等字符截断。
- 路径过长或含特殊字符时，移动到较短路径（如 `D:\pms\expert-pack`）再试。
- MCP 宿主中建议直接用绝对路径，避免宿主工作目录与预期不一致。

### 5）中文乱码

- Python 侧：设置 `$env:PYTHONIOENCODING = "utf-8"` 或 `$env:PYTHONUTF8 = "1"`；控制台可 `chcp 65001`。
- 文件编码：所有文档/代码统一 UTF-8（无 BOM）；CLI 的 JSON 输出已 `ensure_ascii=False`。
- MCP 宿主：`mcp_server.py` 启动时会把 stdout/stderr 切到 UTF-8；若宿主仍乱码，在 `env` 中加 `PYTHONIOENCODING=utf-8` 兜底。
- 不要用 ANSI/GBK 另存 SKILL.md 或 spec。

### 6）MCP 宿主不显示工具 / 启动失败

- 检查 `args` 中 `mcp_server.py` 路径是否存在；`command` 用 `python` 时确保宿主能解析（否则换绝对路径）。
- 查看宿主 MCP 日志（stderr）：协议错误、`SPEC_NOT_FOUND`、Python 异常都会出现在那里。
- 确认 JSON 合法（不能有注释、尾逗号）。
- 本包保证 stdout 只输出协议消息；如果在 `mcp_server.py` 之外（包装脚本/宿主环境）向 stdout 打印内容，会破坏协议，请改为打印到 stderr。
- 修改配置后需重启宿主或重新连接 MCP。

### 7）安装后技能未触发

- 确认 `identify.md` / 各 `SKILL.md` 的 `description` 与触发词已发布（重启宿主后会重新加载）。
- 确认专家包与 12 个子技能均已安装（`skills` 目录下有 12 个子目录，含 2 个底座、3 个深能力技能）。
- 明确说出触发词，如「变电智能问数」「设备台账」「缺陷」「检修」「可靠性」「专题图」「健康评估」「故障诊断」「诊断报告」。

### 8）发布失败 / 包体超限

- 平台单包上限 10MB：检查技能目录是否误带数据文件、缓存、日志；`build_pack.py` 会在本地先做同样的校验。
- 缺 `SKILL.md`、frontmatter `slug`/`displayName` 缺失、`name` 与目录名不一致都会导致发布或构建失败；先跑 `build_pack.py --validate-only` 或 `skillhub publish <技能目录> --dry-run`。
- 权限不足：确认 `skillhub login` 使用的 Key 对目标组织/命名空间有发布权限。
- 分析底座发布包必须含 `config/scorecard.json`、`config/diagnosis_rules.json`、`templates/` 下 3 个模板与 `assets/demo_bundle.json`，缺一项构建即失败（其他技能也不得误带这些文件）。

### 9）分析 MCP 工具不可见 / 分析结果异常

- 工具不可见：确认 `args` 指向 `skills/substation-analysis-mcp/scripts/analysis_mcp.py`，且宿主日志（stderr）无 Python 异常；重新连接 MCP 后应显示 7 个工具。
- 分析结果为空或置信度很低：通常是 bundle 缺段（如未提供 `defects`/`tests`/`load`）——看输出里的 `completeness`、`dataGaps`，按 `references/bundle-schema.md` 补齐**真实取数**，不要用推测值填。
- 分数与预期不符：核对 `config/scorecard.json` 的权重/阈值与 `timeWindow.end`（超期判定基准）；评分卡需业务校准，不要直接改代码。
- 报告里有 `{{占位符}}`：payload 缺键，按 `list_report_types` 返回的 `requiredPayloadKeys` 补齐后再生成。

### 10）知识库检索不到 / 工具名对不上

- 工具名以腾睿work 平台实际配置为准：`search` / `retrieve` / `query` 只是常见命名示例，本包不绑定具体名称（见 06 文档 3.5 节）。
- 检索为空时如实写「知识库未检索到相关条款」，**不得虚构条款号或条文**；需要时调整 `knowledgeQueries` 的关键词后重试。
- 引用片段必须来自检索结果原文、保留 `title`/`source`/`snippet`/`kbId`，不得改写或拼接。
