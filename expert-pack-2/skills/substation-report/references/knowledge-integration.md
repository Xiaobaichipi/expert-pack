# 报告专家 · 知识库集成与引用规范（WeKnora MCP）

> 本文件是 `substation-report` 的细节层：知识库检索怎么接、`citations` 怎么组、片段怎么保真、检索不到怎么写。
> 前提事实：内网 **WeKnora 知识库已构建完成，并已在「腾睿work」（AgentScope 智能体平台）中以 MCP 方式调通**；
> **具体工具名与参数名以平台实际配置为准**，本文件只给语义映射与调用纪律，不硬编码任何工具名。
> 合规底线：知识库只提供**条款检索与引用**，不参与评分、不改写分析结论、不虚构条款。

## 一、在链路中的位置

```
数据 MCP 取数 → bundle → 分析 MCP 计算
                              ↓
                    knowledgeQueries[]（引擎给出的检索建议）
                              ↓
                 WeKnora MCP 检索（腾睿work 已挂载）
                              ↓
              citations[{title, source, snippet, kbId}]
                              ↓
        generate_report(report_type, payload, citations, title)
```

- 检索建议**只能来自**分析工具返回值：`assess_device_health.knowledgeQueries`、`assess_station_health.knowledgeQueries`、`diagnose_equipment.hypotheses[].knowledgeQueries`。
- 不得由 LLM 临时编检索词去「找一条支持自己结论的条款」。

## 二、工具语义映射（名称以平台为准）

| 语义动作 | 平台常见工具名形态 | 常见参数 | 使用纪律 |
|---|---|---|---|
| 语义检索条款 | `search` / `retrieve` / `knowledge_search` / `weknora_search` 等 | `query`（检索语句）、`top_k` 或 `limit`（返回条数） | 先用平台页面/MCP 列表确认实际工具名与参数，再调用；本文不硬编码 |
| 按文档取详情（可选） | 平台侧「按文档/分块取详情」类工具（名称以平台为准） | 文档或分块 ID | 仅当检索结果缺少 `snippet` 时按需调用，不臆造字段 |

**调用前必做**：在腾睿work 的 MCP 工具列表里确认（1）工具名 （2）参数名（`query` 是否叫 `text`/`keywords`）（3）返回结构（是否含 `title`/`source`/`content`/`docId`/`chunkId`）。确认后把结果映射到统一 `citations` 字段。

**检索请求示例（参数对象，非工具调用语法；参数名以平台为准）**

```json
{"query": "危急缺陷 消缺时限 规程要求", "top_k": 5}
```

## 三、检索流程（逐条、可追溯）

1. **取检索建议**：从分析结果中按顺序取 `knowledgeQueries[]`（一般 2-5 条）。
2. **逐条检索**：一条 query 一次调用，`top_k` 建议 3-5；不要把所有 query 拼成一句。
3. **相关性判定**：只保留与「设备类型 + 部位 + 结论方向」匹配的条目；明显不相关的丢弃（丢弃数量在自检记录中说明）。
4. **去重**：同一文档同一分块只保留一次。
5. **保真摘录**：把命中内容原文写入 `snippet`（见第四节）。
6. **组 citations**：按第四节字段规范整理。
7. **传入渲染**：`generate_report(..., citations=[...])`；正文引用格式见第五节。
8. **无命中处理**：按第六节声明，不得用通用常识替代。

## 四、`citations` 字段规范

| 字段 | 类型 | 来源 | 要求 |
|---|---|---|---|
| `title` | string | 知识库返回的文档/条款标题 | 原文，不改写；缺失时用文档名 + 章节 |
| `source` | string | 标准号/规程名/章节出处 | 平台未返回标准号时写文档名，**禁止编标准号** |
| `snippet` | string | 命中片段原文 | **保真**：不改写、不概括、不拼接、不翻译；超长可截断并用「…」标注 |
| `kbId` | string | 知识库文档或分块标识 | 平台未返回时用空字符串 `""` 并在报告「数据质量」注明「知识库未返回文档标识」 |

**示例（字段形态示意，内容为示例）**

```json
[
  {"title": "电力变压器检修导则（示例标题）", "source": "DL/T 573（示例）", "snippet": "示例：套管油位异常时应结合介损与油色谱分析判断受潮程度。", "kbId": "kb-doc-001"},
  {"title": "变电设备缺陷管理规定（示例标题）", "source": "示例单位规程 第4.2节", "snippet": "示例：危急缺陷应在 24 小时内组织处理并履行验收手续。", "kbId": "kb-doc-002"}
]
```

## 五、引用格式与呈现

1. **正文引用**：在引用到的句子后加 **【来源：标题】**（标题与 `citations[].title` 完全一致）。
2. **文末列表**：报告末尾「引用」章节逐条列：`【来源：标题】source：snippet`。
3. **多条款并列**：`【来源：标题A】【来源：标题B】`，顺序与 `citations` 数组一致。
4. **编号**：如渲染器已生成编号，沿用渲染器编号，不另造一套。

## 六、检索不到 / 不相关 / 未挂载

| 情形 | 判定 | 声明话术（可直接用） |
|---|---|---|
| 无命中 | 检索返回空 | 「知识库未检索到相关条款。」+ 说明检索词与知识库范围 |
| 命中但不相关 | 与设备类型/部位/结论方向不匹配 | 「知识库未检索到与该设备/部位直接相关的条款（已检索：{query}）。」 |
| 知识库 MCP 未挂载 | 工具列表无检索工具 | 报告「数据质量」章节写「本次未引用规程条款（知识库 MCP 未挂载）」。 |
| 命中但无出处处号 | 缺 `source` | 用文档名/章节替代，并在「数据质量」注明「引用出处以文档名为准」。 |

**禁止**：编造条款号、编造标准号、把通用常识包装成规程条文、把历史对话内容当知识库证据。

## 七、合规与质量边界

- **不改分**：条款只解释规则与给出依据，**不得以条款为由修改分数、等级、置信度（`confidence`）或假设顺序**，也不得据此改写 `dataGaps`/`missingEvidence`；如需调整，应回到分析层改数据/改规则配置并重跑。
- **时效**：涉及具体数值要求（时限、阈值）时注明「以现行有效版本为准」「以本单位规程为准」。
- **脱敏**：知识库内容如含人员姓名、联系方式、详细地址，引用时脱敏（保留姓氏/单位）。
- **权限**：仅检索当前账号有权访问的知识库范围，不跨权限试探、不导出整库内容。
- **可追溯**：每条引用都要能回到「哪次检索、哪个文档/分块、哪段原文」；报告附件保留 citations 原始 JSON。

## 八、引用质量自检

- [ ] 每条 `citations` 都能对应一次检索调用（query + 结果）。
- [ ] `snippet` 与知识库返回原文一致，未概括、未拼接。
- [ ] `title`/`source` 未编造标准号或条款号。
- [ ] 正文每处【来源：标题】都能在文末列表找到同标题条目。
- [ ] 无命中时已按第六节声明，未用常识替代。
- [ ] 引用未影响任何分数、等级、假设顺序。
- [ ] 「数据质量」章节写明了知识库可用性与引用数量。

## 九、常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 硬编码某个工具名（如把 `search` 写死） | 平台改名后整条链路失败 | 以平台配置为准，调用前确认 |
| 把多条查询拼成一句 | 召回质量差、引用错位 | 一条 query 一次调用 |
| 概括片段后当引用 | 违反保真要求，无法核查 | 原文摘录或写「未检索到」 |
| 检索不到就删掉引用章节 | 读者误以为无规程依据需求 | 写明「知识库未检索到相关条款」 |
| 用条款推翻分析结论 | 越权、结论不可复现 | 回分析层重跑，不在报告层改 |
| `kbId` 缺失时编一个 | 无法回溯 | 留空并注明 |
