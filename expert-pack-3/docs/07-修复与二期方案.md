## 二、修复范围（expert-pack）

### A1. 12 个 `SKILL.md` frontmatter 补 `slug` / `displayName`

- 在每个 `skills/<slug>/SKILL.md` 的 `name:` 之后插入：
  - `slug: <目录名>`
  - `displayName: <原 metadata.display_name>`
- 约束：UTF-8 无 BOM、LF 换行、不改动其他字段。
- 验收：12 个技能逐个 `skillhub publish --dry-run` 通过。

### A2. `manifest.json` 对齐平台清单

- 源清单改为平台可识别的精简形态（作者只需维护这些）：

  ```json
  {
    "manifestVersion": "1",
    "type": "skillset",
    "slug": "bianya-intelligent-data-qa",
    "displayName": "变电智能问数",
    "summary": "...",
    "scene": "（可选）",
    "subScene": "（可选）",
    "skillSlugs": [ ... 12 个 ... ]
  }
  ```

- `skills[]`、`files[]` 不再手写：由 `build_pack.py` 从各技能 SKILL.md frontmatter
  与 identify.md 字节**构建时生成**（单一事实源，避免双重维护）。
- `scene`/`subScene` 按平台约定由网页端选择，本地仅透传（选填）。

### A3. `build_pack.py` 产物与校验

- 产物：
  - `dist/skills/<slug>.zip` × 12（不变）；
  - `dist/<pack-slug>-bundle.zip` = 构建生成的 `manifest.json` + `identify.md`
    （对齐平台真实清单包；原 `-install.zip` 更名，语义更准确）；
  - `dist/checksums.txt`（不变）。
- 移除旧「网页导出格式」`dist/<pack-slug>.zip`（非平台格式，避免误上传）；
  `_clean_artifacts` 同时清理历史同名产物。
- 新增校验：
  - SKILL.md：`slug` == 目录名、`displayName` 非空、`version` 为 SemVer、
    `name` == slug、`description` 非空；
  - manifest：平台字段与类型、顺序契约（两个底座在前、总控在最后）；
  - bundle：仅含 `manifest.json` + `identify.md`；`files[]` 的 sha256/size 与
    identify.md 字节一致；`skills[]` 与 `skillSlugs` 顺序一致。
- 保持确定性：固定 zip 时间戳、JSON 序列化顺序固定。

### A4. 文档修正

- `docs/03-部署与使用说明.md`：发布要求补 `slug`/`displayName`；构建产物表改为
  12 技能包 + 1 清单包；`pack install --dir` 指向 Agent 全局技能目录；安装结果 13 个目录；
  删除「网页导出格式与平台一致」「上传 zip 优先」等错误表述。
- `docs/04-开发与扩展指南.md`：发布前检查清单补 frontmatter 三字段；产物命名更新。
- `README.md`：产物表、快速开始同步。

## 三、二期：expert-pack-2（接口模拟补全 + 鉴权）

### B1. 目标

> 落地状态：B1–B5 已于 2026-10-28 完成（实现见 `skills/pms-gateway-mcp/scripts/mock_gateway/` 与
> `pms_client/signing.py`，验证见 [docs/09](09-模拟网关与鉴权.md) 第八节与 [docs/08](08-修复记录.md) S6–S7）。

把 `expert-pack` 复制为 `expert-pack-2`，在**不改动原包**的前提下：

1. 为 26 个 PMS 接口补全**可运行的模拟数据**（当前 `spec.interfaces[].mock` 已有 26 份样例，
   但只覆盖单对象；二期补齐列表/分页/多对象/关联主键一致的数据集）；
2. 提供**可鉴权的本地模拟网关**（token / appkey 两种模式），让
   `pms_client` 走真实 HTTP + 鉴权链路（而非 mock 直出），从而可端到端测试 MCP / CLI；
3. 全部可离线运行、确定性输出、仅标准库；
4. 测试与文档齐备。

### B2. 架构（已落地，详见 [09-模拟网关与鉴权](09-模拟网关与鉴权.md)）

```
expert-pack-2/skills/pms-gateway-mcp/scripts/
├─ mock_gateway/
│  ├─ server.py     # ThreadingHTTPServer + 26 条路由（按 spec path/method 注册）
│  ├─ auth.py       # token / appkey 鉴权（±300s 时间窗、nonce 防重放）
│  ├─ data.py       # 26 接口确定性数据集（站点/设备/缺陷/隐患/故障/检修/巡视/可靠性/资源/拓扑）
│  └─ __init__.py   # start_server / MockGatewayServer / MockAuth / data 导出
├─ pms_client/signing.py   # appkey 签名唯一实现（客户端与网关共用）
└─ pms_client/auth.py      # build_appkey_signature 委托 signing（不再抛 TODO）
```

- 请求：沿用 `pms_client.transport` 的 path 替换、query/body 编码规则；
- 响应：`{"code":0,"message":"ok","data":...,"meta":{...}}`，列表接口带
  `pageNo/pageSize/total`，与 `extract_list/extract_total` 兼容；
- 鉴权：
  - `token`：`Authorization: Bearer <token>`，凭证来自 `PMS_TOKEN`（默认
    `mock-token-001`，可用 `PMS_MOCK_TOKEN` 覆盖）；
  - `appkey`：`X-PMS-App-Key`/`X-PMS-Timestamp`/`X-PMS-Nonce`/`X-PMS-Signature`，
    签名 = `HMAC-SHA256(secret, app_key\nmethod\npath\ncanonical_query\nbody_sha256\ntimestamp\nnonce)`
    （canonical_query：None 跳过、列表逗号、布尔小写、排序后 urlencode），
    时间窗 ±300s，nonce 防重放；
  - 失败：HTTP 401/403 + `{"code":401/403,...}`，客户端归一为 `AUTH_FAILED`。
- 数据一致性：同一 assetId/psrId 在台账、缺陷、检修、可靠性、拓扑接口中指向同一设备；
  分页、过滤（站/设备/等级/时间）生效；未知主键返回空列表而非报错。

### B3. 启动与使用

```powershell
$env:PMS_GATEWAY_BASE_URL = "http://127.0.0.1:18080"
$env:PMS_AUTH_MODE        = "token"
$env:PMS_TOKEN            = "mock-token-001"
python expert-pack-2/skills/pms-gateway-mcp/scripts/pms_cli.py mock-server --port 18080 --auth-mode token

# 另开终端
python expert-pack-2/skills/pms-gateway-mcp/scripts/pms_cli.py doctor
python expert-pack-2/skills/pms-gateway-mcp/scripts/pms_cli.py call get_asset_by_id --params '{"assetId":"AST-102-0001"}'
```

## 五、风险与边界

- **scene/subScene**：官方公开目录无电力类目，企业平台类目未确认；本地清单不强制，
  由网页端选择，避免写入无效枚举值。
- **appkey 签名**：真实中台签名规范未提供，二期实现的是「模拟规范」，客户端
  `pms_client/signing.py` 与本地模拟网关共用同一实现；正式接入只替换 `signing.py`。
- **平台上传入口**：CLI 无 pack 上传命令，清单包上传需企业网页端验证；
  `-bundle.zip` 形状已对齐平台下载物，但平台是否接受导入需企业环境实测。
- **DSH 沙箱**：`pack install`/临时目录 chmod 在沙箱内可能失败，模拟网关测试全部
  使用 127.0.0.1 + workspace 内临时目录，避免依赖平台与外部网络。
