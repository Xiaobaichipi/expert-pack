> **数据来源与核对说明**
>
> - **工具名、接口编码、接口地址、典型问数**：来自 `expert-pack/spec/interfaces.json`（唯一事实源），本表逐字引用。
> - **接口名称、所属中心、能力域**：来自原始《变电智能问数_26接口功能说明》一栏表；已与 spec 中的 `title` / `path` 做交叉核对，26/26 一致。
> - **所属技能、角色**：来自 `spec.groups[].skill` / `spec.groups[].role`，与 `manifest.json` 的 `skillSlugs` 一致。
> - **当前状态**：`spec.status = inferred`。即接口地址、参数与返回字段均为**依据原始说明文档与平台命名惯例推断的占位规格**；正式《接口说明文档》下发后需按 [04-开发与扩展指南](04-开发与扩展指南.md) 修订 spec。

>
> **v1.1.0 增补**：第一～三节（26 个 PMS 数据接口）**保持原样未改动**；新增第四节「v1.1 分析工具映射」，说明 `spec/analysis-tools.json` 中的 7 个分析工具与技能/角色的对应关系。分析层的数据流与集成见 [06-深能力与知识库集成](06-深能力与知识库集成.md)。

## 三、编码与归属约定

接口编码格式为 `pgp-<中心编号>-<版本段>-<接口编号>`，前缀可辅助判断归属：

| 前缀 | 所属中心 |
|---|---|
| `pgp-101-*` | 电网资源中心（PSR：资源台账、设备树） |
| `pgp-102-*` | 电网资产中心（资产台账、厂家信息） |
| `pgp-103-*` | 电网图形中心（专题图 SVG） |
| `pgp-104-*` | 电网拓扑中心（电源点、供电范围） |
| `pgp-105-*` | 作业资源中心（智能装备、仪器仪表） |
| `pgp-106-*` | 作业管理中心（缺陷、隐患、故障、检修、巡视、试验） |
| `pgp-108-*` | 电网分析中心（可靠性、可开放容量） |

> 说明：前缀与中心的对应关系由 26 条接口编码归纳得出，属于**约定性归纳**，不是平台公开规范；新增接口时以服务目录中的实际编码为准。

**分析工具 vs 数据接口的边界**

- 分析工具**入参只有 bundle 或分析数据**（如 `defects`），不接收站名/设备名等自然语言参数，也不自行调用 26 个数据接口。
- 分析工具**不返回原始台账字段**；需要台账/缺陷明细时由调用方另行经数据 MCP 获取。
- 报告中的每个数字都应能追溯到 bundle 字段与接口编码（`sourceMeta.interfaceCode`）；知识库条款只以 `citations` 形式附加，不参与计算。

## 五、字段口径提示

- **接口地址**：表中 `{assetType}` 为路径占位符，调用时需替换为实际设备类型（如 `transformer`），详见 `spec/interfaces.json` 中该工具的 `params[].in = "path"`。
- **请求方式**：`GET` 走 query 参数；`POST` 走 JSON body；个别接口为 path + query 混合，详见 spec 的 `paramStyle`。
- **返回结构**：spec 的 `responseHint` 给出 `kind`（`object` / `paged` / `list`）、`dataKey` 与 `listKey`，是网关层统一解包的依据。
- **Mock 数据**：每个工具在 spec 的 `mock` 字段内置一条样例响应，`PMS_AUTH_MODE=mock` 时直接返回，用于无凭证联调；正式联调前所有回答必须标注「Mock 数据」。
- **能力域**：本表沿用原始说明文档的划分（一次设备、综合检索、缺陷管理、隐患管理、故障管理、检修计划、检修作业、巡视管理、作业标准管理、供电可靠性、电网运行分析、作业资源、厂家型号、专题图、电源分析、停/供电分析）；`spec.groups` 按业务主题合并为 6 组，两者是「业务分组」与「平台能力域」两个视角，不冲突。
